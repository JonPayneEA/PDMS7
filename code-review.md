# Code review

Carried out 2026-11-02, alongside commenting the whole code base. Version 0.4.0 plus the guides
merged after it.

## Scope and method

Every source file was read in full: the R package (`R/`, about 8,900 lines), the compiled core
(`src/pdm_core.c`, `src/pdm_core.h`, `src/pdm_engine.cpp`), the standalone golden checker
(`tools/core/check_golden.c`) and the tests (`tests/testthat/`, 136 tests). The two files
generated by cpp11 (`R/cpp11.R`, `src/cpp11.cpp`) were read but not commented, since they are
regenerated.

The hydrological core was checked against its equations, not just read: the five capacity
distributions and their inverses (including the join of the two halves of the triangular
storage function at m - w/12), the exact routing solutions (linear, power-law recession, the
quadratic store's Riccati solution, the exponential store's logistic solution, the two-store
cascade and its equal-constant series), Moore's transfer coefficients (Eq. 27), evaporation
(Eq. 8), standard and demand recharge (Eq. 10 and 13), the fractional outlet delay and its
steady-state queue, the steady-state start, PACK's water balance and cover memory, the
Yilmaz et al. (2008) flow-duration signatures, KGE, and the threshold contingency scores.
No error was found in any of them.

The commenting itself changed no code. Every R file was checked by comparing its parse tokens
before and after, and every C and C++ file by comparing comment-stripped preprocessor output.
Lint is clean under lintr 3.1.1 and 3.4.0, all 4,909 tests pass, and the standalone golden
checker passes every case. One earlier commit re-wrapped lines an old formatter had broken after
operators; that too is layout only, verified the same way.

## Findings

Severity: **medium** means a result or a future change could be wrong without anyone noticing;
**low** means an edge case, an inconsistency or a performance cost; **info** means worth knowing,
no action needed. None is high: nothing found gives a wrong answer in normal use today.

### Medium

| # | Where | Finding | Suggested remedy |
|---|---|---|---|
| 1 | `calibrate_pdm()`, the calibration log's runs | Every trial starts from `initial_state()`: routing stores empty. With a slow groundwater store and a short warm-up, the store is still filling when scoring begins, which biases `kb` and `kg` towards values that fill it faster. | Start from `initial_state_from_flow()` at the first observed flow, as the articles recommend, or require a minimum warm-up. A change of behaviour, so for decision. |
| 2 | `src/pdm_engine.cpp` | The 40-field parameter vector is unpacked into `pdm_params` three times. A layout change must be made in three places, and a slip in one would show only in that function's tests. | One `fill_params()` helper, as `fill_route()` already is for routes. |

### Low

| # | Where | Finding | Suggested remedy |
|---|---|---|---|
| 3 | `.with_lock()` | Stale-lock recovery races: two sessions that both find a lock older than ten minutes can each delete it, the second deleting the first's fresh lock, so both write. The numbering check catches a duplicate on the next write but does not prevent it. | Record the holder's PID and host in the lock and remove a stale lock only when its holder is gone. |
| 4 | `.append_csv()` (run log, batch status) | Rows are appended without a header once the file exists. A later version that adds or reorders a column would write rows that read back misaligned. Same stale-lock race as 3, at one minute. | Compare the existing header before appending; refuse or start a new file on mismatch. |
| 5 | `validate_candidate()`, `propose_candidate()` | The latest candidate is read before the lock and not re-checked inside it, so a candidate proposed by another session in between is missed. `test_candidate()` and `sign_off_project()` do re-check. | Re-check inside the lock, as the other two do. |
| 6 | `sign_off_project()` (design) | A Steward who wrote a trial, calibration, candidate, validation or test cannot sign off, as agreed. One who registered the data or selected the structure can. | Decide whether those choices should also bar sign-off. |
| 7 | `calibration_app()` | The identity typed in the app is set as global options and not restored when the app closes, so later code in the session writes entries under it. | Save the options at start and restore them with `shiny::onStop()`. |
| 8 | `initial_state_from_flow()` | If the baseflow share needs more soil storage than Smax, the soil is capped silently and the run starts out of balance. | Warn, naming the shortfall. |
| 9 | `FlodePackModel`, `FlodePackState` | The only S7 classes declared without `package = "pdmS7"`, so their names print without the prefix and could collide with another package's. | Add the package; check that saved states still load. |
| 10 | `calibrate_pdm_multi()` | Searches every parameter linearly, unlike `calibrate_pdm()`. A parameter spanning orders of magnitude, such as `kb`, is then sampled almost entirely near the top of its range. | Add `log_scale`. |
| 11 | `pdm_hindcast()` | With state correction on a model with an outlet delay, the whole hindcast fails deep inside, because `correct_state()` refuses `td > 0`. | Check at the start with a clear message. |
| 12 | `compare_structures()` | The comparison id is a timestamp to the second; two comparisons written by a script in the same second would be ranked together. | Add a random or entry-based suffix. |
| 13 | `correct_state()` | The soil gain `gg` multiplies a flow error (mm/h) to change a storage (mm), so it carries units of hours; for a cascade, only the downstream store is adjusted. Both defensible, both undocumented. | Say so in the help for `state_updater()`. |
| 14 | `FlodePdmModel` | `qc` may be negative, so simulated flow can go negative in dry weather. Probably intended for abstractions. | Document it. |
| 15 | `calibrate_pdm()` | A failing trial scores 1e30; under L-BFGS-B, a finite-difference step onto a failing trial gives an enormous gradient and can stall that start. Rare with the shipped bounds. | Note in the help; Nelder-Mead is unaffected. |
| 16 | `pareto_front()` | Compares every archived trial with every other; the archive holds every objective call, which can reach thousands. | A sort-based front. |
| 17 | `verify_project(rerun = TRUE)` | Reloads and re-checksums the registered data for every entry it reruns. | Load each registration once. |
| 18 | `` `%||%` `` | Defined in `project_report.R` but used across the package. From R 4.4 it also masks base R's identical operator. | Move to `utils.R`. |
| 19 | `tools/core/check_golden.c` | The CSV reader merges consecutive commas, so an empty field would shift later columns silently; allocation results are not checked. Developer tool; the golden files have no empty fields. | Parse fields explicitly; check allocations. |

### Information

| # | Where | Note |
|---|---|---|
| 20 | `.path_set()` | Creates a missing key where `.path_get()` refuses one. Every caller reads first, so typos cannot slip through today; keep that order. |
| 21 | AR fitting | `fit_error_updater()` uses maximum likelihood; `pdm_hindcast(fit_window =)` uses least squares, which tolerates gaps. Both reasonable; the difference should be documented. |
| 22 | Checksum chain | An edit to the newest entry is detected only once another entry follows it. Recorded in the design; a sign-off seals everything before it. |
| 23 | `.run_jobs()` | Parallel workers load the installed package, not a development copy. |
| 24 | `read_pdm_config()` | Refuses any line containing `!expr`, even in a YAML comment. Deliberately strict. |
| 25 | `initial_state_from_flow()` | The steady state ignores evaporation. Fine as documented. |

## Fixed during the review

- A comment describing the sensitivity plot's shared scale sat above the performance-diagram
  function; moved to the function it describes.
- The design record's entry schema said "one of the ten types"; there are eleven since the test
  window was added.
- An earlier formatter's awkward line breaks were re-wrapped (layout only).

## Decisions and fixes after the review

Decided 2026-11-02 by the Owner.

| # | Decision | Done in |
|---|---|---|
| 1 | Start every calibration trial and logged run in steady state at the first observed flow. `calibrate_pdm()` gains `start` (default `"flow"`); `register_data()` records the rule, and projects registered earlier keep the soil start so their records still reproduce. Articles whose synthetic data started from empty stores now start in steady state, and every claim in their text was rechecked. | 0.4.1 |
| 2 | One `fill_params()` helper in the C++ binding. | 0.4.1 |
| 3 | Stale locks are moved aside and re-checked before deletion, so a fresh lock is put back rather than deleted; one routine serves the log and the CSV files. | 0.4.1 |
| 4 | Appending to a CSV with different columns is refused with a message. | 0.4.1 |
| 5 | `validate_candidate()` re-checks the candidate under the lock. (`propose_candidate()` reads no latest entry, so it needed no change; the finding over-stated it.) | 0.4.1 |
| 6 | Sign-off independence stays as designed: registering data or selecting the structure does not bar a Steward. | No change |
| 7 | The app restores the identity options when the session ends. | 0.4.1 |

The remaining low and information items stand as recorded, for when the code they touch next
changes.
